# Seed data format

How the Blind 75 seed problems are authored, built, verified and stored.

## Layout

| Path | What | Written by |
|---|---|---|
| `blind75-list.json` | The 75 problems (order, title, slug, difficulty, topic) from neetcode.io | browser read, checked by `tools/check-list.js` |
| `batches.json` | Which slugs belong to each batch | hand |
| `spec/<slug>.js` | Statement (markdown), constraints, signature, example explanations, optional `post` / `drivers` / `limits` / `notes` | hand |
| `tools/gen/<slug>.js` | `samples` (3 inputs), `hidden(rng)` (seeded hidden inputs), `validate(args)` (constraint check) | hand |
| `reference/<slug>/solution.cpp`, `solution.java` | Reference solutions (C++14 / Java 13) | hand |
| `reference/<slug>/wrong*.cpp\|java` | Wrong solutions the tests **must** reject | hand |
| `reference/<slug>/slow*.cpp\|java` | Correct but slow solutions; verdicts are reported, not required | hand |
| `problems/<slug>.json` | The seedable problem document | `tools/build.js` |
| `verify-results.json`, `verify-report.md` | Last verification of every problem | `tools/verify.js` |
| `verified.json` | slug -> sha256 of `problems/<slug>.json` that passed verification | `tools/verify.js` |

## Commands (run from `backend/`)

```
node seed/tools/io-selftest.js          # shared C++/Java I/O library on Judge0
node seed/tools/build.js --batch 1      # or <slug...> / --all
node seed/tools/verify.js --batch 1     # or <slug...> / --all
```

Both tools call `src/services/judgeService.js`, so programs are built (`driverCode` with `{{USER_CODE}}`
replaced) and submitted (base64 batch, C++ flags `-Wall -Werror=return-type`) exactly as for a user.

## Problem document (`problems/<slug>.json`)

Every top-level key except `seedMeta` is a field of `src/models/problem.js`; `seed.js` writes only those.

- `slug`: the file name, the key `seed.js` upserts by, and the problem's page URL (`/problems/<slug>`).
  Required by the model; it equals what `src/utils/slug.js` generates from the title (checked by
  `tests/seed-problems.test.js`), so a problem created earlier in the admin UI (and slugged by
  `scripts/addSlugsToProblems.js`) is matched and updated instead of duplicated.

- `examples`: the 3 samples. `input` is display text (`nums = [1,2,3]`), `output` is the reference's output.
- `visibleTestCase`: sample 1 (what Run executes).
- `hiddenTestCases`: all tests, samples first (what Submit executes). At most 10, each input and output <= 200 KB.
- `codeSnippets`: per language, `userSnippet` (starter) and `driverCode`, generated by `tools/lib/codegen.js`.
- `referenceSolutions`: copied from `reference/<slug>/` (shown on the Solution tab after solving).
- `seedMeta`: order, NeetCode slug, limits, signature, per-test notes and sizes. Not stored in MongoDB.

Expected outputs are never written by hand: `build.js` takes them from the C++ reference's stdout on Judge0.

## Canonical value format (stdin and stdout)

Input is one value per line, in parameter order. Output is the return value on one line.
The drivers accept any whitespace between tokens on input, but always print exactly this form:

| Type | Form | Example |
|---|---|---|
| int, long | decimal, `-` for negatives | `-42` |
| bool | `true` / `false` | `true` |
| string | double quotes; `"` and `\` escaped with `\`; printable ASCII only | `"a \"b\" \\ c"` |
| char | one-character string | `"x"` |
| array / list | `[` elements separated by `,` `]`, no spaces; nested the same way | `[[1,2],[],[3]]` |
| null | `null` | `null` |

This is JSON restricted to integers, booleans, printable-ASCII strings and arrays, so generators
serialise values with `JSON.stringify`.

### Structures and special inputs

| Kind | Format | Example |
|---|---|---|
| Linked list | values from head to tail; `[]` is null | `[1,2,3]` |
| Array of lists | array of lists | `[[1,4],[],[2]]` |
| Binary tree | level order, `null` for a missing child, trailing nulls removed; `[]` is null | `[1,null,2,3]` |
| Tree node reference | the node's (unique) value; the driver looks it up in the tree parameter | `5` |
| Unsigned 32-bit | decimal 0..4294967295 (Java receives the same bits in an `int`) | `4294967293` |
| Graph (Clone Graph) | adjacency list, node values 1..n, `adjList[i]` = neighbours of node i+1 | `[[2,4],[1,3],[2,4],[1,3]]` |
| Design problem | line 1: operation names; line 2: argument lists; output: one result per call, `null` for constructor/void | `["Trie","insert","search"]` / `[[],["a"],["a"]]` -> `[null,null,true]` |
| Median (double) | one decimal place | `2.5`, `-3.0` |

Driver-only inputs: Linked List Cycle reads `pos` after the list; the driver links the tail to node `pos`
(-1 = no cycle) and passes only `head`. In-place (void) methods print the mutated parameter after the call
(Rotate Image, Set Matrix Zeroes, Reorder List).

Code generation lives in `tools/lib/codegen.js` (types, starters, drivers), `tools/lib/structs.js` (list
and tree node types and helpers) and `tools/lib/design.js` (operation replay). Clone Graph, Encode/Decode
Strings and Serialize/Deserialize Binary Tree have hand-written drivers in their spec files.

Judge0 compares stdout with the expected output after removing trailing whitespace from each line and
trailing blank lines. Everything else must match exactly, which is why drivers print one canonical form.

### Problems with several correct answers

The driver normalises the user's result before printing (spec `post`), for example sorting the two indices
in Two Sum, or each triplet and then the list in 3Sum. The normalisation lives only in the driver, never in
the user's code. Alien Dictionary goes further: the driver checks the returned order against the words and,
if it is valid, prints the alphabetically smallest valid order, so every correct answer prints the same thing.
Where sorting cannot make answers comparable, the generator only produces tests with a unique answer
(Longest Palindromic Substring, Minimum Window Substring, Top K Frequent Elements).

## Language notes

- C++ compiles as C++14 (GCC 9.2, no `-std` flag): no structured bindings, `std::optional`, `if constexpr`.
  A non-void function that can end without `return` is a compile error, so starters return a placeholder.
- Java is OpenJDK 13 (no records, no text blocks). The user's `class Solution` sits before `public class Main`.
- Driver names start with `oc_` / live in `namespace oncode` (C++) or `Main` (Java) to avoid clashing with user code.
