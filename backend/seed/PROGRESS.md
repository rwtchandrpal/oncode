## Platform facts (from Phase 0)
- Program = driver code with `{{USER_CODE}}` replaced by the user's code (`src/services/judgeService.js`).
- Languages: `cpp` -> Judge0 54 (GCC 9.2.0, flags `-Wall -Werror=return-type`); `java` -> 62 (OpenJDK 13, class `Main`).
  Probed: C++ is **C++14** (`__cplusplus` = 201402): no structured bindings, `std::optional`, `if constexpr`.
  A missing `return` in a non-void function is a compile error. Java reports feature version 13 (no records, no text blocks).
- Test case = `{ input: <stdin string>, expectedOutput: <stdout string> }`; batch (max 20 per request), base64.
- Output comparison (probed on both languages): trailing whitespace on each line (including `\r`) and trailing blank
  lines are ignored. Everything else is exact: a leading blank line, a leading space, a double space between tokens,
  a blank line in the middle, or a case difference is Wrong Answer. Drivers must print canonical output exactly.
- Run = `visibleTestCase` only. Submit = `hiddenTestCases` only. Admin create/update validates references on `hiddenTestCases`.
- No per-problem limits are sent: Judge0 defaults apply (5 s CPU, 10 s wall, ~3 GB). Batch max 20. Backend deadline 30 s per batch.
